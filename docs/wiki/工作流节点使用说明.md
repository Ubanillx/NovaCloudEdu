## 基本操作

### 添加节点

- 从**左侧浮动工具栏**展开节点分类，将节点**拖拽**到画布空白区域
- 开始节点和结束节点全局唯一，已添加后不可重复拖入

### 连线

- 从节点**右侧圆点**（输出 Handle）拖拽到另一节点**左侧圆点**（输入 Handle）即可连线
- 不允许自环（节点连接自己）和重复连线
- 连线代表执行顺序：上游节点执行完成后，沿连线流向下游节点

### 删除

- 选中节点后按 `Delete` 或 `Backspace` 键删除
- 也可在右侧配置面板底部点击「删除节点」

### 快捷键

| 快捷键 | 功能 |
|--------|------|
| `Ctrl/⌘ + S` | 保存 |
| `Ctrl/⌘ + Z` | 撤销 |
| `Ctrl/⌘ + Shift + Z` | 重做 |
| `Delete / Backspace` | 删除选中节点 |

### 注释

- 通过浮动工具栏的「注释」按钮在画布中心添加注释卡片
- 注释节点不参与执行，仅用于备注说明

## 触发节点

### 开始 (START)

**作用**：工作流的入口，每个工作流有且仅有一个。

**连线规则**：
- 只有**输出** Handle（右侧），没有输入
- 从右侧圆点连线到下一个要执行的节点

**配置项**：
| 配置 | 说明 |
|------|------|
| 触发方式 | API 调用 / Webhook / 定时触发 / 事件触发 |
| 输入参数 | 定义工作流接收的参数（名称、类型、描述、是否必填、默认值） |
| 校验输入 | 开启后执行时会校验参数类型和必填项 |

**使用示例**：
```
[开始] → [LLM 模型] → [结束]
```

添加输入参数 `query`（类型 String、必填），执行工作流时需要传入 `query` 参数值。

---

### Webhook / 定时触发

**作用**：由外部 Webhook 或定时任务触发工作流。

> 当前版本这两类触发节点的配置与开始节点类似，后续会扩展 Webhook URL 配置和 Cron 表达式配置。

## AI 节点

### LLM 模型 (LLM)

**作用**：调用大语言模型进行文本生成。

**连线规则**：
- 左侧输入 Handle + 右侧输出 Handle
- 从上游节点连入，执行后沿右侧连线传递结果

**配置项**：
| 配置 | 说明 |
|------|------|
| 模型 | GPT-4o Mini / GPT-4o / DeepSeek Chat / 通义千问 Plus |
| 系统提示词 | 模型的 System Prompt |
| 温度 | 0-2，控制生成的随机性 |
| 最大 Token | 生成的最大 Token 数 |

**输出变量**：`result`、`response`、`model`、`tokensUsed`

---

### 知识库检索 (KNOWLEDGE_RETRIEVAL)

**作用**：从指定知识库中检索与输入相关的文档片段。

**配置项**：
| 配置 | 说明 |
|------|------|
| 知识库 ID | 目标知识库的 ID |
| 检索数量 (Top K) | 返回最相关的 K 条结果（1-20） |
| 相似度阈值 | 最低相似度分数（0-1） |

**输出变量**：`results`、`documents`、`matchCount`

---

### 意图识别 / 实体抽取

**作用**：
- **意图识别**：识别用户输入的意图类别
- **实体抽取**：从文本中提取结构化实体信息

连线和使用方式与普通节点一致。

## 逻辑节点

### 条件分支 (CONDITION)

**作用**：根据条件判断结果选择不同的执行路径。

**连线规则**：
- 左侧输入 Handle
- 右侧有**两个**输出 Handle：
  - **上方**（默认 Handle）：条件为 true 时走这条线
  - **下方**（橙色 Handle）：条件为 false 时走这条线

**配置模式**：

#### 模式一：单条件（向后兼容）

不添加任何条件分支时，节点以单条件模式运行。配置 variable / operator / compareValue，结果为 true 走上方出边，false 走下方出边。

```
         ┌──（true）──→ [节点A]
[条件分支] ─┤
         └──（false）──→ [节点B]
```

#### 模式二：多条件分支

点击「添加分支」配置多个条件，按顺序匹配，第一个满足的分支生效，全部不满足走默认分支。

> ⚠ **重要**：多条件模式下，所有匹配结果（含 default）都走**上方默认出边**，下方橙色出边不会被触发。建议删除下方连线，避免混淆。

每个分支支持两种条件类型：
- **可视化模式**：选择变量 → 选择运算符 → 填写比较值
- **公式模式**：编写表达式，如 `${score} > 80`

**支持的运算符**：`==`、`!=`、`>`、`>=`、`<`、`<=`、`contains`、`startsWith`、`endsWith`、`isEmpty`、`isNotEmpty`

**使用示例**：
```
[开始(query)] → [LLM(分类)] → [条件分支] ──→ [处理A]
                                           ──→ [处理B]
```

---

### 多路分支 (SWITCH)

**作用**：类似 switch-case，根据变量值匹配多个分支。

**连线规则**：与条件分支相同（上方 + 下方两个输出 Handle）。

> ⚠ **重要**：Switch 所有 Case（含 default）均走**上方默认出边**，下方橙色出边永远不会被触发。

**配置项**：
| 配置 | 说明 |
|------|------|
| 判断变量 | 用于匹配的变量名 |
| Case 分支 | 每个 Case 可选「值匹配」或「公式」模式 |

- **值匹配**：精确比较判断变量与 Case 值（均转字符串比较）
- **公式模式**：支持自定义表达式，如 `${score} > 80`

按顺序匹配，首个命中的 Case 生效，无匹配走默认分支。

---

### 循环 (LOOP)

**作用**：重复执行一段子工作流。拖入画布后显示为一个**容器**，可以在容器内部放入子节点。

**连线规则**：

循环容器有 **4 个 Handle**：

| Handle | 位置 | 说明 |
|--------|------|------|
| input（输入） | 容器左上角 | 外部节点连线到这里进入循环 |
| output（输出） | 容器右上角 | 循环结束后从这里连到后续节点 |
| loop-start（蓝色圆点） | 容器内部左侧 | 从这里连线到循环体**第一个**子节点 |
| loop-end（橙色圆点） | 容器内部右侧 | 循环体**最后一个**子节点连线到这里 |

**使用步骤**：

1. 从工具栏拖拽「循环」到画布，出现一个矩形容器
2. 从工具栏拖拽其他节点（如「设置变量」「LLM」等）**放入容器内部**
3. 从容器内部左侧的**蓝色圆点**连线到第一个子节点
4. 将子节点串联起来
5. 从最后一个子节点连线到容器内部右侧的**橙色圆点**
6. 将外部上游节点连到容器左上角的 **input**
7. 将容器右上角的 **output** 连到下游节点

```
                     ┌─────── 循环容器 ────────┐
                     │                         │
[上游] → (input)     │  ● → [子节点] → [子节点] → ●  │     (output) → [下游]
                     │ 蓝                     橙 │
                     └─────────────────────────┘
```

**循环类型**：

| 类型 | 说明 | 关键配置 |
|------|------|----------|
| forEach | 遍历数组 | 数组变量、当前元素变量名（默认 `item`） |
| for (count) | 指定次数 | 循环次数、计数器变量名（默认 `index`） |
| while | 条件循环 | 条件表达式（如 `${retryCount} < 3`） |

**通用配置**：
- **索引变量名**：当前迭代的索引（默认 `index`）
- **最大迭代次数**：上限 1000，防止死循环
- **结果变量名**：每次迭代结果收集到此数组中（默认 `loopResults`）

**输出变量**：`loopResults`（结果数组）、`loopCount`（实际迭代次数）、`loopCompleted`（是否全部完成）

> 容器可以拖拽边框调整大小（选中后显示调整手柄）。

### 并行 (PARALLEL)

**作用**：同时执行多个分支，等待分支完成后汇总结果。

**连线规则**：
- 左侧输入 Handle + 右侧输出 Handle
- 与普通节点一样连线

> ⚠ **重要**：并行节点**不是**通过连线来定义分支，而是需要在**右侧配置面板**中显式配置分支。

**使用步骤**：

1. 在画布上放置并行节点和各分支要执行的节点
2. 点击选中并行节点，打开右侧配置面板
3. 在「并行分支」区域点击 **+ 添加**
4. 为每个分支填写名称，并在「入口节点」下拉框中选择该分支从哪个节点开始执行
5. 配置等待策略、超时、合并策略等
6. 将并行节点的输出连线到后续节点（如合并节点）

```
               分支1入口（配置面板中选择）
              ↗ [节点A] → [节点B]
[上游] → [并行]                        → [合并/下游]
              ↘ [节点C] → [节点D]
               分支2入口（配置面板中选择）
```

**配置项**：

| 配置 | 说明 |
|------|------|
| 等待策略 | `ALL`（全部完成）/ `ANY`（任一完成）/ `N_OF_M`（完成 N 个） |
| 超时 (ms) | 分支执行超时时间，默认 60000ms |
| 快速失败 | 开启后任一非 optional 分支失败时终止其余分支 |
| 并行分支 | 每个分支需配置：名称、入口节点、结果变量名、是否可选 |
| 结果合并策略 | `OBJECT`（按变量名合并）/ `ARRAY`（收集为数组）/ `FIRST` / `LAST` |

> ⚠ **竞态风险**：并行分支共享变量上下文，多分支同时修改同一变量会导致数据竞争。建议每个分支使用独立的结果变量名。

---

### 合并 (MERGE)

**作用**：将多个上游分支的数据汇聚为一个变量，通常放在并行节点之后。

**连线规则**：
- 左侧输入 Handle + 右侧输出 Handle
- 可以接收多条入边（来自多个上游分支）

**配置项**：

| 配置 | 说明 |
|------|------|
| 合并模式 | `all`（合并全部为 Map）/ `first`（取第一个非空值）/ `last`（取最后一个非空值） |
| 来源变量 | 指定要合并的变量名列表（为空时合并所有上游变量） |
| 输出变量名 | 合并结果存入此变量（默认 `merged`） |

**使用示例**：
```
[并行] → [分支A] ──┐
                   ├──→ [合并] → [结束]
[并行] → [分支B] ──┘
```

## 数据处理节点

### 设置变量 (VARIABLE_SET)

**作用**：创建或修改全局变量。支持多个变量同时赋值。

**操作类型**：

| 操作 | 说明 |
|------|------|
| 设置 (set) | 仅在变量**不存在**时赋值 |
| 覆盖 (overwrite) | 用变量引用或固定值替换已有值 |
| 清空 (clear) | 将变量置为空 |
| += / -= / *= / /= | 对数值型变量进行四则运算 |

**使用示例**：在循环体内用 `+= 1` 实现计数器递增。

---

### 获取变量 (VARIABLE_GET)

**作用**：读取全局变量的值。

**配置项**：
- **变量名**：要读取的变量（可从上游变量列表中选择）
- **默认值**：变量不存在时使用此值
- **输出变量名**：读取结果存入此变量（默认 `value`）

---

### JSON 解析 (JSON_PARSE)

**作用**：JSON 字符串解析、对象序列化、字段提取。

**操作类型**：

| 操作 | 说明 |
|------|------|
| Parse | JSON 字符串 → 对象 |
| Stringify | 对象 → JSON 字符串 |
| Extract Field | 按路径提取字段值（如 `data.items.0.name`） |

---

### 模板渲染 (TEMPLATE)

**作用**：使用模板语法生成文本，支持变量插值。

**模板语法**：使用 `{{变量名}}` 引用变量，支持嵌套访问 `{{user.name}}`。

**使用示例**：
```
尊敬的 {{name}}，

您的查询结果如下：
{{result}}
```

配置面板中可以点击上游变量按钮快速插入。

---

### 代码执行 (CODE)

**作用**：执行自定义 JavaScript 代码。

**配置项**：
- **语言**：JavaScript（默认）/ Python（需后端支持）
- **代码**：所有上游变量可直接作为全局变量使用，通过 `return` 返回结果
- **输出变量名**：代码返回值存入此变量（默认 `result`）

**代码示例**：
```javascript
// 上游变量 text 可直接使用
const summary = text.slice(0, 100);
return { summary, wordCount: text.length };
```

## 输出节点

### 结束 (END)

**作用**：工作流的出口，每个工作流最多一个。

**连线规则**：
- 只有**输入** Handle（左侧），没有输出
- 从上游节点连线到左侧圆点

**配置项**：
- **输出变量映射**：定义工作流执行完成后返回的变量
  - 可从上游可用变量列表中快速选择
  - 也可手动添加映射（输出名 ← 来源变量）
  - 未配置时，自动透传所有上下文变量

## 变量系统

### 变量传递规则

1. **开始节点的输入参数**作为初始变量进入上下文
2. 每个节点执行后，其**输出变量**自动写入全局上下文
3. 下游节点可以使用上游所有节点产出的变量
4. 配置面板中的「选择变量」下拉框会自动发现可用的上游变量

### 变量引用语法

| 场景 | 语法 | 示例 |
|------|------|------|
| 条件/Switch 表达式 | `${变量名}` | `${score} > 80` |
| 模板渲染 | `{{变量名}}` | `尊敬的 {{name}}` |
| 代码执行 | 直接使用变量名 | `const x = text.length` |

### 各节点默认输出变量

| 节点类型 | 输出变量 |
|----------|----------|
| LLM | `result`、`response`、`model`、`tokensUsed` |
| 知识库检索 | `results`、`documents`、`matchCount` |
| 条件/Switch | `conditionResult`、`branch`、`matchedBranch` |
| 循环 | `loopResults`、`loopCount`、`loopCompleted` |
| 并行 | `branchResults` |
| 合并 | `merged` |
| HTTP 请求 | `response`、`statusCode`、`headers`、`body` |
| 代码执行 | `result`、`output` |
| JSON 解析 | `result`、`parsed` |
| 数据库查询 | `result`、`rows`、`rowCount` |

## 常见问题

### Q: 保存时报「缺少开始节点」但画布上明明有？

刷新页面后如果立即操作可能会遇到短暂的状态同步延迟。请等待页面完全加载后再保存。如果问题持续，请检查浏览器控制台日志。

### Q: 条件分支的下方出边（橙色）不生效？

如果配置了**多条件分支**（添加了条件分支列表），则所有分支结果都走上方默认出边，下方橙色出边仅在单条件模式下有效。建议在多条件模式下删除下方连线。

### Q: 并行节点报「未配置有效分支」？

并行节点需要在**右侧配置面板**中手动添加分支并为每个分支选择入口节点，仅有连线不够。

### Q: 循环容器内怎么添加节点？

直接从左侧工具栏拖拽节点放入循环容器的矩形区域内即可。注意：不能在循环内放置「开始」「结束」「循环」节点。

### Q: 循环容器内的连线怎么接？

1. 从容器内部左侧的**蓝色圆点**（loop-start）拖线到第一个子节点
2. 子节点之间正常连线
3. 从最后一个子节点拖线到容器内部右侧的**橙色圆点**（loop-end）

### Q: 变量下拉框为什么是空的？

变量列表通过分析上游连线自动发现。请确保：
1. 当前节点有通过连线与上游节点相连
2. 上游节点已配置好输出（如设置变量节点已添加变量赋值）
