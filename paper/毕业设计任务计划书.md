# 毕业设计任务计划书

**课题名称：** 基于大语言模型的智慧教育云平台设计与实现

---

## 一、毕业论文的主要内容

本课题以大语言模型（Large Language Model，LLM）为技术核心，设计并实现一套面向K12及高等教育场景的AI驱动智慧教育云平台——"智云星课"（NovaCloudEdu）。平台将大语言模型深度融入教学、学习、考试、批改等教育全流程，旨在解决传统教育模式中个性化需求难以满足、教学资源分布不均衡、教学效果评估方式单一等核心痛点。论文主要内容如下：

**（一）研究背景与研究现状分析**

梳理教育数字化转型的政策背景与现实需求，分析国内外智慧教育平台的发展现状与不足，调研检索增强生成（RAG）、AI工作流编排、多模态大模型、智能批改与学情分析等前沿技术领域的研究进展，提出本文的研究目标与研究内容。

**（二）系统需求分析**

从功能需求和非功能需求两个维度对平台进行系统化分析。功能层面围绕学生、教师、管理员三类角色建立完整的用例体系，涵盖AI智能对话、课程学习、智能批改、在线考试、工作流编排、知识库管理、实时音视频通话与直播、每日学习、社交互动、学情分析、会员管理等核心业务场景；非功能层面明确系统在响应性能、并发能力、数据安全、可用性、可扩展性等方面的量化指标要求。

**（三）系统总体架构设计**

采用领域驱动设计（DDD）方法，将教育业务划分为28个业务子域，设计"接口层—应用层—领域层—基础设施层"四层架构。数据存储层集成PostgreSQL（含pgvector向量扩展）、Redis、Elasticsearch、Neo4j多类型存储引擎，面向不同数据特征选择最优存储方案。系统采用微服务容器化架构，通过Docker Compose进行服务编排，并提供Web管理端（React + TypeScript）与Flutter跨平台移动端双端应用。

**（四）AI核心模块设计与实现**

这是本文的核心章节，详细阐述以下七大AI模块的设计思路与实现方案：

1. **多模型统一适配层：** 基于Langchain4j框架设计ChatModelFactory工厂模式，实现对通义千问、DeepSeek、GPT-4o、智谱GLM、Moonshot、Ollama等六大LLM供应商的统一封装与无缝切换，通过SSE（Server-Sent Events）机制实现流式Token推送。

2. **可视化AI工作流引擎：** 设计支持有向无环图（DAG）拓扑的工作流执行引擎，实现16种节点类型的图形化编排（含LLM节点、CODE节点、RAG节点、条件分支、并行执行、MCP工具调用、联网搜索等），使教师能够通过拖拽方式构建复杂AI教学任务流程。

3. **RAG知识库检索增强生成系统：** 实现多格式文档解析（PDF/Word/TXT）、智能文本分块、向量嵌入生成、pgvector向量相似度召回与Rerank语义精排的完整两阶段检索流程，显著提升AI回答的领域准确性。

4. **MCP工具调用协议集成：** 基于Anthropic MCP（Model Context Protocol）开放协议，实现AI模型与外部工具的标准化交互，支持联网搜索、数据库查询、文件操作等工具的动态发现与调用。

5. **OCR+LLM全链路智能批改系统：** 基于视觉语言模型实现手写作业结构化OCR识别，结合LLM逐题语义评阅、6维错因分类（概念理解、计算错误、知识遗忘等）、学生知识画像构建和基于错因与知识点的同类题自适应推荐，形成"识别—批改—画像—推荐"完整闭环。

6. **AI智能出题系统：** 实现支持联网热点新闻搜索、几何图形（线段、圆、角等）自动渲染、AI辅助配图的试题生成功能，辅助教师高效命题与组卷。

7. **AI PPT生成助手：** 基于Multi-Agent架构（规划Agent、内容Agent、设计Agent、评估Agent）实现智能演示文稿生成，集成多模态视觉审查与反思修复循环，提升生成质量。

**（五）系统关键功能实现**

介绍平台非AI核心功能的实现，包括：基于WebRTC + Go信令服务的三级降级策略实时音视频通话（P2P→TURN中继→LiveKit SFU）；基于SRS（Simple Realtime Server）的RTMP推流与HTTP-FLV/HLS在线直播；课程视频学习与学习进度管理；基于Typst排版引擎的在线考试系统；每日签到打卡、文章阅读与单词记忆等每日学习功能；帖子发布、评论、点赞等社交互动；基于Elasticsearch的全文检索；以及React Web端与Flutter移动端的前端实现。

**（六）系统测试与部署**

设计并执行功能测试（各模块核心流程验证）、性能测试（AI接口响应时延、并发吞吐量）和安全测试（认证鉴权、SQL注入、XSS防护），详细说明基于Docker Compose的容器化一键部署方案，涵盖后端服务、数据库、向量库、搜索引擎、缓存、AI推理服务等全栈组件。

**（七）总结与展望**

总结本文的主要研究成果与创新点，分析当前平台在知识图谱集成、多模态学情建模等方面的不足，展望面向个性化自适应学习的未来工作方向。

## 二、毕业论文的基本要求/技术指标、原始数据资料及重点参考文献要求

### （一）基本要求与技术指标

**1. 功能完整性要求**

- 平台须完整实现学生、教师、管理员三类用户角色的核心功能，覆盖AI对话、课程学习、智能批改、在线考试、工作流编排、知识库管理、音视频通话与直播等不少于10个业务模块；
- 同时提供Web管理端（PC浏览器访问）和Flutter移动端（Android/iOS双平台）两套完整客户端应用；
- AI工作流引擎须支持不少于10种节点类型的图形化编排与运行。

**2. 性能与响应指标**

- 普通API接口（非AI生成类）P99响应时延须低于500 ms；
- AI流式生成接口首Token延迟（TTFT）须低于3 s，用户交互流畅度满足正常使用体验；
- 智能批改OCR识别阶段处理时间（单份作业）须低于10 s；
- 系统在模拟50并发用户场景下整体可用性须达到99%以上；
- RAG知识库检索在知识库规模不超过1,000个文档块时，向量检索召回耗时低于500 ms。

**3. AI能力质量指标**

- LLM供应商集成须不少于3家（如通义千问、DeepSeek、Ollama本地模型），实现无损切换；
- RAG系统须通过"稠密向量召回 + Rerank精排"两阶段检索架构，相较纯关键词检索显著提升回答相关性；
- 智能批改须支持通用作业（GENERAL）与试卷（EXAM_PAPER）两种批改模式，逐题输出得分、错因分类与改进建议。

**4. 安全性要求**

- 所有接口须基于JWT Token实现身份认证，敏感操作须进行角色权限校验（RBAC）；
- AI接口须集成会员配额管理，防止资源滥用；
- 代码执行节点（CODE节点）须在隔离沙箱（GraalJS / Docker容器）中运行，禁止访问宿主机文件系统与网络。

**5. 工程规范要求**

- 后端采用Spring Boot + 领域驱动设计（DDD）四层架构，领域模块划分合理，职责边界清晰；
- 代码须具备必要的注释说明，核心业务逻辑须有对应的单元测试或集成测试；
- 论文须包含完整的系统架构图、关键模块流程图（时序图/流程图），图表须规范、清晰；
- 论文字数不少于2万字（中文），参考文献不少于20篇，其中英文文献不少于10篇，近五年文献占比不低于60%；
- 须附有不少于3,000词的英文摘要或翻译外文资料一篇（原文不少于3,000词）。
