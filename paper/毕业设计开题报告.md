# 毕业设计开题报告

**课题名称：** 基于大语言模型的智慧教育云平台设计与实现

---

## 一、研究意义、研究现状、研究内容、拟采用的研究思路与方法

### （一）研究意义

**1. 理论意义**

教育数字化转型已成为全球教育发展的核心趋势。党的二十大报告作出"推进教育数字化"的重要战略部署，教育部于2024年启动人工智能赋能教育行动，明确提出开发教育领域人工智能大模型、推动智慧教育平台智能升级的战略目标。孙立会等学者指出，生成式人工智能融入智慧教育平台能够系统化重构教育体系，推动组织架构、教学范式、教学过程与评价方式的全方位创新与变革[1]。然而，当前教育平台在集成AI能力时普遍面临AI功能碎片化、缺乏统一工作流编排能力、大语言模型存在幻觉问题与知识检索精度不足等问题，难以满足教育场景对智能化的深层需求。

本课题探索大语言模型与教育场景深度融合的系统架构设计方法，通过引入领域驱动设计（DDD）理念对教育业务进行子域划分，结合检索增强生成（RAG）、AI工作流编排、MCP工具调用等前沿技术构建统一的AI能力框架，为AI驱动的智慧教育平台建设提供可参考的架构设计范式。

**2. 实践意义**

从实践层面看，本课题构建一个可落地的全栈智慧教育云平台——"智云星课"（NovaCloudEdu），涵盖AI对话、知识库管理、工作流编排、智能批改、在线考试、课程学习、音视频互动等核心教育场景。通过实际开发与测试验证RAG检索增强、可视化工作流引擎、OCR+LLM智能批改等关键技术在教育领域的可行性和有效性，为教育数字化转型提供工程实践样本。同时，平台覆盖Web管理端和跨平台移动端，满足教师教学管理与学生移动学习的双重需求，具有较高的实用价值。

### （二）研究现状

**1. 智慧教育平台研究现状**

在国际层面，主流在线教育平台已开始探索AI技术的深度集成。Coursera引入AI驱动的课程推荐和自动评估功能，Khan Academy推出基于GPT-4的个性化辅导助手Khanmigo，Duolingo利用大语言模型实现自适应语言学习和智能对话练习。在国内，学而思推出了基于大模型的学习助手，猿辅导在自动批改和智能出题方面进行了深入研究，科大讯飞依托语音识别和NLP技术在智慧课堂领域建立了较为完整的产品体系。孙立会等学者指出，教育专用大模型可以扮演私人导师、智能学伴和贴身助教三重角色，分别以引导式方法、苏格拉底式对话和差异化教学支持服务于学生与教师[1]。

然而，现有智慧教育平台仍存在共性局限：（1）AI功能多以独立模块形式嵌入，缺乏跨模块的协同能力；（2）知识检索大多基于关键词匹配，语义理解和精准召回能力不足；（3）缺乏灵活的AI任务编排机制，教师难以根据教学需要自定义AI处理流程；（4）多数平台仅覆盖部分教育场景，未能形成教、学、考、评的完整闭环。

**2. 检索增强生成（RAG）技术研究现状**

RAG是解决大语言模型知识更新滞后和幻觉问题的核心技术方案。Liu等人[3]和Gao等人[4]分别从方法论和技术演进角度对RAG进行了系统综述，梳理了从朴素RAG到高级RAG再到模块化RAG的发展脉络。在检索环节，Karpukhin等人[5]提出的DPR开创了基于稠密向量的段落检索范式；Gao等人[6]提出的HyDE实现了无需标注数据的零样本稠密检索；Sarthi等人[7]提出的RAPTOR通过递归抽象处理构建树状组织结构，增强了对长文档多层次语义的检索能力。在精排环节，Weller等人[8]提出的Rank1方法利用测试时计算显著提升了重排序精度。在向量索引方面，Malkov等人[22]提出的HNSW图索引在高维向量近似最近邻搜索中具有优异表现，Xiao等人[16]发布的C-Pack资源包为中文向量嵌入提供了高质量模型与基准。

**3. AI智能体与工作流编排研究现状**

随着大语言模型能力增强，AI智能体（Agent）和工作流编排成为研究热点。Arai[9]探讨了基于Dify平台和DSL构建本地化RAG与AI Agent系统的方案。Zhang等人[10]提出的ReusStdFlow框架为智能体系统的动态工作流构建提供了标准化可复用方案。此外，Anthropic提出的MCP（Model Context Protocol）开放协议定义了AI模型与外部工具交互的标准接口，使智能体能够动态发现和调用外部服务，进一步扩展了AI工作流的能力边界。

**4. 智能批改与学情分析研究现状**

传统的自动批改主要针对客观题的答案匹配，对主观题的评阅长期依赖人工。随着OCR技术和大语言模型的进步，基于"OCR识别+LLM语义评阅"的智能批改方案成为可能。Onyenwe等人[15]研究了LaTeX公式在计算机化考试中的集成方案。在学情分析领域，李晓理等人[2]深入探讨了知识图谱与大语言模型的协同共生模式，指出知识图谱的结构化知识存储和可解释推理能力可以有效弥补LLM的幻觉问题，二者联合应用于教育领域能够在个性化学习、智能教学资源生成、智能评估反馈等方面发挥重要作用。

**5. 多模态大模型与AI演示文稿生成研究现状**

文本生成图像技术在教育内容创作中展现出广阔前景。Liao等人[11]探索了文生图技术在美术教育中的应用；Ma等人[13]对视频扩散生成技术进行了全面综述；Rong等人[14]评估了文生视频模型在语言教学中辅助写作构思的效果。在AI演示文稿生成方面，Zheng等人[17]提出PPTAgent实现了超越简单文字转幻灯片的演示文稿生成与评估；Bandyopadhyay等人[18]提出了基于LLM的多阶段端到端幻灯片生成方案；Gupta[19]系统研究了利用LLM自动生成演示文稿的方法。

### （三）研究内容

围绕"将大语言模型深度融入教育全流程"的核心目标，本课题的研究内容主要包括以下六个方面：

**1. 基于DDD的教育平台架构设计。** 采用领域驱动设计方法，将教育业务划分为28个子域，设计"接口层—应用层—领域层—基础设施层"四层架构。数据存储层集成PostgreSQL（含pgvector向量扩展）、Redis、Elasticsearch（含IK中文分词）、Neo4j四种存储引擎，面向不同数据特征选择最优存储方案。

**2. 多模型统一适配与流式对话技术。** 基于Langchain4j框架设计ChatModelFactory工厂模式，实现对通义千问、DeepSeek、GPT-4o、智谱GLM、Moonshot、Ollama等6大LLM供应商的统一封装与无缝切换，通过SSE（Server-Sent Events）机制实现流式Token推送，支持文本与多模态两种输入模式。

**3. RAG知识库检索增强生成系统。** 实现多格式文档解析（PDF/Word/TXT）、智能文本分块、DashScope Embedding向量化、基于HNSW索引的pgvector向量相似度召回和Rerank语义精排的完整两阶段检索流程，支持知识库与AI助手的灵活绑定。

**4. 可视化AI工作流引擎设计与实现。** 设计支持有向无环图（DAG）拓扑的工作流执行引擎，实现LLM节点（集成RAG检索、MCP工具调用、联网搜索、JSON结构化输出）、CODE节点（GraalJS沙箱 + Docker Python隔离）、条件分支、并行执行、循环、HTTP请求、数据库查询等16种节点类型，使教师能够通过拖拽方式构建复杂AI教学任务。

**5. OCR+LLM全链路智能批改系统。** 基于视觉语言模型实现手写体结构化OCR识别，结合LLM逐题语义评阅、6维错因分类、学生知识画像构建和基于错因与知识点的同类题自适应推荐，形成"识别—批改—画像—推荐"完整闭环。Flutter端集成ML Kit实现端侧实时文字检测。

**6. 实时音视频通话与直播系统。** 使用Go语言开发WebSocket信令服务，实现P2P→TURN中继→LiveKit SFU三级降级策略的实时通话；集成SRS直播服务器实现RTMP推流与HTTP-FLV/HLS分发，支持公开直播与班级专属直播。

### （四）拟采用的研究思路与方法

**1. 总体研究思路**

本课题采用"需求分析→架构设计→模块实现→测试验证"的工程化研究路线。首先通过文献调研和教育场景分析明确系统需求；然后基于DDD方法进行架构顶层设计和领域建模；接着按模块逐步实现各子系统，重点攻克RAG检索增强、AI工作流引擎、智能批改等核心技术难点；最后通过功能测试、性能测试和安全测试验证系统的可行性与有效性。

**2. 具体研究方法**

（1）**文献研究法：** 系统调研RAG检索增强、AI工作流编排、MCP协议、智能批改、音视频通信等领域的最新学术成果与技术方案，为系统设计提供理论依据。

（2）**领域驱动设计方法：** 采用DDD的战略设计（子域划分、限界上下文识别）和战术设计（聚合根、实体、值对象、仓储模式），将复杂教育业务分解为28个高内聚、低耦合的领域模块，确保架构的可维护性与可扩展性。

（3）**原型迭代法：** 采用增量迭代的开发方式，优先实现核心AI模块（多模型适配、RAG知识库、工作流引擎）的最小可用版本，在此基础上逐步扩展智能批改、音视频通话、AI出题、PPT生成等功能模块，每个迭代周期进行功能验证与优化调整。

（4）**实验验证法：** 设计功能测试用例覆盖各模块核心流程（AI对话、工作流执行、RAG检索、智能批改等），使用性能测试工具测量关键接口的响应时延与并发吞吐量，验证系统在实际教学场景中的可用性。

（5）**对比分析法：** 将RAG两阶段检索（向量召回+Rerank精排）与纯关键词检索进行效果对比，验证检索增强对AI回答质量的提升；将不同LLM供应商在教育场景下的生成质量进行横向对比，为模型选型提供依据。

**3. 技术路线**

```
需求分析 → DDD领域建模（28子域） → 架构设计（四层架构 + 多存储引擎）
    ↓
后端核心实现：
    Spring Boot 3 + MyBatis-Plus + Spring Security(JWT/RBAC)
    ↓
AI核心模块实现：
    多模型适配层(Langchain4j) → RAG知识库(pgvector+Rerank) → AI工作流引擎(16节点)
    → MCP工具调用 → 智能批改(OCR+LLM) → AI出题 → AI PPT生成(Multi-Agent)
    ↓
关键功能实现：
    音视频通话(Go+WebRTC三级降级) → 直播(SRS) → 课程学习 → 在线考试(Typst)
    → 每日学习 → 社交互动 → 全文搜索(ES) → 会员配额
    ↓
前端实现：
    Web管理端(React 18 + TypeScript + TailwindCSS)
    Flutter移动端(iOS/Android, ML Kit端侧OCR)
    ↓
容器化部署(Docker Compose 12+容器) → 功能测试 + 性能测试 + 安全测试
```
