# 第二章 相关技术概述

## 2.1 后端开发技术

### 2.1.1 Spring Boot 3 框架

Spring Boot是Java生态中最主流的微服务开发框架，本文采用Spring Boot 3作为后端主框架。Spring Boot 3基于Jakarta EE 10规范，要求JDK 17+运行时，具备自动配置（Auto-Configuration）、起步依赖（Starter Dependencies）、Actuator运行时监控等核心特性，能够大幅简化企业级应用的配置与部署。

在安全方面，本文集成Spring Security框架，采用JWT（JSON Web Token）实现无状态身份认证，结合RBAC（基于角色的访问控制）模型实现细粒度权限管理，支持学生、教师、管理员三种角色的差异化访问控制。在实时通信方面，本文利用Spring WebSocket模块和STOMP协议实现服务端消息推送，支持聊天、弹幕等实时交互场景。

### 2.1.2 领域驱动设计（DDD）

领域驱动设计（Domain-Driven Design, DDD）是一种以业务领域为核心的软件设计方法论。其核心概念包括聚合根（Aggregate Root）、值对象（Value Object）、领域服务（Domain Service）和仓储（Repository）等。聚合根作为一致性边界的入口，封装业务规则；值对象通过属性值定义身份，保证不可变性；仓储接口定义在领域层，实现在基础设施层，从而解耦业务逻辑与数据访问。

本文采用DDD四层架构：接口层（interfaces）负责外部请求的接收与响应转换；应用层（application）协调领域对象完成用例流程；领域层（domain）封装核心业务规则；基础设施层（infrastructure）提供技术实现支撑。将DDD应用于教育平台具有显著价值：教育业务包含课程、考试、批改、知识库、工作流等多个复杂子域，通过DDD的子域划分和限界上下文（Bounded Context）机制，能够有效降低模块间的耦合度，提升系统的可维护性和可扩展性。

### 2.1.3 MyBatis-Plus 持久化框架

MyBatis-Plus是MyBatis的增强工具，在不改变MyBatis原有特性的基础上提供了通用CRUD操作、代码生成器、分页插件、乐观锁等实用功能。本文采用MyBatis-Plus作为持久化框架，通过注解式SQL结合条件构造器（LambdaQueryWrapper）实现类型安全的数据访问，同时利用其分页插件统一处理列表查询的分页逻辑，减少重复代码的编写。

## 2.2 数据存储技术

### 2.2.1 PostgreSQL 与 pgvector 向量扩展

PostgreSQL是功能最强大的开源关系型数据库之一，支持JSONB非结构化数据存储、数组类型、全文搜索等高级特性。本文采用PostgreSQL 16作为主数据库，并集成pgvector向量扩展，实现业务数据与向量数据的统一存储与管理。

pgvector扩展为PostgreSQL添加了向量数据类型和相似度搜索能力。在向量索引方面，pgvector支持IVFFlat和HNSW两种索引类型。其中HNSW（Hierarchical Navigable Small World）索引基于分层可导航小世界图的思想，Malkov等人[22]的研究表明其在高维向量的近似最近邻搜索中具有优异的效率和鲁棒性。本文采用HNSW索引配合余弦相似度（cosine distance）计算方法，为RAG知识库的向量检索提供高效的底层支撑。相较于采用独立的向量数据库（如Milvus、Pinecone），pgvector方案避免了额外的运维复杂度，同时保证了业务数据与向量数据的事务一致性。

### 2.2.2 Redis 缓存与会话管理

Redis是高性能的内存键值存储系统，支持字符串、哈希、列表、集合、有序集合等多种数据结构。本文采用Redis 7作为缓存与会话管理引擎，主要应用于三个场景：分布式会话管理（存储JWT Token对应的用户信息）、AI使用配额的原子计数（通过Redis的INCR命令保证并发场景下配额扣减的原子性）以及实时通信中的用户在线状态追踪。

### 2.2.3 Elasticsearch 搜索引擎

Elasticsearch是基于Lucene的分布式搜索与分析引擎，其核心是倒排索引（Inverted Index）技术。Mackenzie等人[25]对高效内存倒排索引的理论与实践进行了深入研究，揭示了倒排索引在大规模文本检索中的性能优势。本文集成Elasticsearch 8.x并安装IK中文分词器，支持ik_max_word（细粒度分词）和ik_smart（智能分词）两种模式，并配置自定义词典以覆盖教育领域的专业术语。Mu等人[26]提出了基于Elasticsearch的实用可视化搜索引擎方案，为本文的多实体全文搜索（课程、书籍、帖子）实现提供了参考。

### 2.2.4 Neo4j 图数据库

Neo4j是全球最流行的图数据库，采用属性图模型（节点+关系+属性）存储数据，特别适合复杂关联关系的建模与查询。本文采用Neo4j 5 Community Edition，使用其声明式查询语言Cypher进行图数据的读写操作。在教育领域，知识图谱能够建立知识点之间的关联关系，便于学生学习深层关联关系，同时也可以与教学资源（教材、试题、视频等）构建关联。李晓理等人[2]指出，知识图谱的结构化知识存储和可解释推理能力与大语言模型的生成能力可以形成协同共生模式，在教育应用中发挥重要作用。

## 2.3 大语言模型相关技术

### 2.3.1 大语言模型（LLM）概述

大语言模型（Large Language Model, LLM）是基于Transformer架构的超大规模神经网络模型，其核心是自注意力机制（Self-Attention），能够捕捉输入序列中任意位置之间的依赖关系。当前主流大模型包括OpenAI的GPT-4o、阿里云的通义千问（Qwen）、DeepSeek、智谱GLM、Moonshot等，各模型在参数规模、训练数据、推理性能和成本上各有优势。在调用大模型时，关键参数包括temperature（控制生成随机性，值越低结果越确定）、top_p（核采样，控制候选词的累积概率阈值）和max_tokens（最大生成长度），合理调优这些参数对生成质量至关重要。

### 2.3.2 Langchain4j 框架

Langchain4j是LangChain的Java实现，提供了一套与大语言模型交互的统一抽象层。其核心接口包括ChatLanguageModel（同步对话）和StreamingChatLanguageModel（流式对话），通过统一的API封装屏蔽了不同模型供应商的接口差异。Langchain4j还提供了ToolSpecification与Function Calling机制，允许LLM在对话过程中自主决策调用外部工具，这是实现AI Agent能力的关键技术基础。本文基于Langchain4j构建了多供应商统一适配层，通过工厂模式封装了通义千问、OpenAI、DeepSeek、智谱GLM、Moonshot、Ollama等6大供应商的模型创建逻辑，业务层仅通过modelId即可透明切换不同模型。

### 2.3.3 RAG（检索增强生成）技术

检索增强生成（Retrieval-Augmented Generation, RAG）是将外部知识检索与大语言模型生成相结合的技术范式，能够有效缓解LLM的知识滞后和幻觉问题[3][4]。其基本流程包括：文档分块→向量嵌入→存入向量数据库（索引阶段），查询向量化→向量相似度召回→检索结果注入Prompt→LLM生成回答（查询阶段）。

在文档分块策略上，本文采用固定大小分块与重叠窗口相结合的方式，以保证分块之间的语义连贯性。在向量嵌入方面，采用DashScope text-embedding-v2模型生成1536维向量。Xiao等人[16]提出的C-Pack方案为通用中文嵌入提供了包括训练数据、嵌入模型和重排序模型在内的完整资源包，为本文的中文文档嵌入提供了参考。

在检索策略上，本文采用“向量召回+Rerank精排”的两阶段检索架构。一阶检索借鉴了稠密检索[5]和零样本检索[6]的思想，通过向量相似度召回候选文档；二阶精排借鉴了Weller等人[8]的重排序研究，使用语义重排序模型对候选文档进行精细排序，显著提升检索结果的相关性。

### 2.3.4 MCP（Model Context Protocol）协议

MCP（Model Context Protocol）是Anthropic提出的开放协议，定义了AI模型与外部工具服务器之间的标准交互接口。MCP采用SSE（Server-Sent Events）作为传输层，核心操作包括三个阶段：initialize（初始化连接）、tools/list（发现可用工具及其参数Schema）和tools/call（执行工具调用并返回结果）。

在AI Agent架构中，MCP扮演着连接LLM与外部能力的桥梁角色。LLM通过MCP发现可用工具后，可以自主决策是否调用工具、传入什么参数，并根据工具返回结果继续推理，从而实现“LLM思考→工具执行→结果反馈→继续思考”的Tool Calling循环。这一机制赋予了AI助手可扩展的能力边界，使其能够访问实时数据、执行计算任务、操作外部系统等。

### 2.3.5 Prompt Engineering 技术

Prompt Engineering（提示工程）是设计和优化输入提示词以引导大语言模型生成高质量输出的技术。在本文的多个AI模块中，Prompt设计是影响生成质量的关键因素。主要技术包括：系统提示词（System Prompt）设计——通过明确的角色定义、任务说明和输出格式约束来规范LLM的行为；Few-Shot提示——通过提供少量示例引导模型理解任务格式；Chain-of-Thought提示——引导模型进行逐步推理以提升复杂任务的准确性；JSON结构化输出引导——通过在Prompt中明确指定JSON Schema来约束LLM输出格式。此外，在多轮对话场景中，本文采用滑动窗口+摘要压缩的上下文管理策略，在控制Token消耗的同时保持对话的连贯性。

## 2.4 前端与移动端技术

### 2.4.1 React + TypeScript

React是Meta开源的前端界面库，本文采用React 18构建Web管理端。React 18引入了Concurrent Mode（并发模式）和Hooks API，能够更高效地管理组件状态和副作用。结合TypeScript类型系统，可以在编译阶段捕捉类型错误，显著提升大型项目的代码质量和可维护性。在UI层面，本文采用TailwindCSS原子化CSS框架实现高效的样式开发，配合shadcn/ui组件库构建统一的设计风格。API层通过OpenAPI Generator自动生成TypeScript客户端代码，确保前后端接口的类型一致性。

### 2.4.2 Flutter 跨平台开发

Flutter是Google开源的跨平台UI框架，采用Dart语言开发，通过自绘引擎（Skia/Impeller）实现跨平台的一致性渲染。本文采用Flutter 3.x构建移动端应用，支持iOS和Android双平台。Flutter的Widget体系采用组合而非继承的设计理念，通过将小粒度Widget组合为复杂界面。在与AI后端的交互中，SSE流式数据的处理是关键技术挑战。本文通过Dio网络库的ResponseType.stream模式实现原始字节流的解析，支持AI对话、智能批改、PPT生成等多个场景的流式Token实时展示。此外，通过平台通道（Platform Channel）与原生能力集成，如Google ML Kit端侧OCR文字检测等。

## 2.5 实时通信技术

### 2.5.1 WebSocket 与信令协议

WebSocket是基于TCP的全双工通信协议，通过HTTP协议升级建立持久连接，适用于实时消息推送场景。本文在两个层面使用WebSocket：一是Java后端基于Spring WebSocket/STOMP实现聊天、弹幕等业务消息推送；二是Go信令服务基于原生WebSocket实现音视频通话的信令转发。

WebRTC（Web Real-Time Communication）是W3C制定的实时音视频通信标准，支持浏览器和移动端之间的P2P直连。在NAT环境下，WebRTC通过ICE（Interactive Connectivity Establishment）框架进行网络穿透，依次尝试STUN（会话穿越工具）和TURN（中继转发）服务器。Paim等人[20]研究了基于P2P中继网络和可编程交换机的NAT穿透方案，为本文的网络穿透策略设计提供了理论参考。

### 2.5.2 直播流媒体技术

在线直播系统的核心是流媒体协议栈。本文采用RTMP（Real-Time Messaging Protocol）作为推流协议，支持OBS等专业推流工具。在拉流分发方面，同时支持HTTP-FLV（低延迟，适合Web端）和HLS（广泛兼容，适合移动端）两种协议。流媒体服务器采用SRS（Simple Realtime Server）v5，它是一款开源的高性能实时视频服务器，支持RTMP收流和HTTP-FLV/HLS分发，并提供回调鉴权机制以确保推流安全性。

## 2.6 容器化与微服务部署

### 2.6.1 Docker 容器化技术

Docker是当前最流行的容器化平台，通过将应用程序及其依赖打包为轻量级容器，实现环境一致性和快速部署。本文利用Docker的多阶段构建（Multi-stage Build）技术优化镜像体积，通过Docker Compose编排多个服务容器的启动顺序和依赖关系。此外，在AI工作流引擎的Python代码沙箱中，采用Docker-in-Docker（DinD）模式为每次代码执行创建独立的隔离容器，通过网络隔离、只读文件系统和执行超时机制保障代码执行的安全性。

### 2.6.2 微服务架构

本文采用“主服务单体+辅助服务微服务”的混合架构模式。核心业务逻辑集中在Java主服务中，避免过度微服务化带来的运维复杂度；同时将PPT生成（Python）、Typst排版编译（Python）、RTC信令（Go）等专业化服务拆分为独立微服务，充分发挥各语言的技术优势。服务间通过REST API、WebSocket和HTTP回调三种方式进行通信，通过Docker Compose的健康检查（healthcheck）和服务依赖（depends_on）机制管理服务启动顺序，确保系统的稳定运行。

## 2.7 本章小结

本章介绍了智云星课平台开发所涉及的核心技术，包括后端框架、多种数据库存储引擎、大语言模型技术栈、前端与移动端框架、实时通信技术以及容器化部署方案，为后续章节的系统设计与实现提供技术基础。
